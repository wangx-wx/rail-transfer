## 一、产品定位

**12306 选票工具**：查票 + 中转方案推荐，帮用户在车次、时间、价格之间做选择。

**核心价值**：官方中转方案被 Top-N 截断，通过**强制枚举候选枢纽**补全。

实测验证（北京南 → 上海，2026-10-07）：

```
官方默认（middle_station 空）      10 条
枚举 15 个枢纽后                  93 条，净新增 83 条
```

每个枢纽都有贡献：合肥南 +10、杭州东 +10、苏州北 +9、南京南 +8、无锡东 +7、武汉 +7、徐州东 +6、天津南 +4。

**注意**：新增方案噪声很大（存在等待 316 分、341 分的垃圾组合），所以工具的价值不只是"补全"，还包括**补全 + 筛选排序**。官方那 10 条里同样混着「等 2 分」和「同车接续」。

## 四、查询流程

```
Step 0  预售期校验（今天 ~ 今天+14），越界明确提示"未开售"
Step 1  直达查询（余票接口，1 次；服务端自动展开全城）
Step 2  官方中转基线（middle_station 留空，1 次）
Step 3  枢纽枚举（15~20 个，每个 1~2 次）
Step 4  合并去重 + 筛选（换乘时间窗）+ 排序
Step 5  价格：直达展示参考价，中转只查第一条
Step 6  买短乘长：仅当直达某车次无票时，用户点该卡片的「查买短乘长」才触发；从离终点最近的经停站往回查，命中即止（D45~D53）
```

**筛选规则**
- 换乘下限：同站 15 分 / 同城异站 60 分
- 超过 120 分：标记「超长等待」，默认折叠（不删除）
- 等待 < 20 分：打风险标记（不隐藏）

### 4.1 请求预算（实测约束）

Cloudflare Workers Free 版硬限制（官方文档，2026-09-05）：

| 限制 | Free | 说明 |
|---|---|---|
| 子请求 / invocation | **50** | 一次请求能发出的外部 fetch 数 |
| 内部服务子请求 / invocation | **1,000** | Service Bindings 调用不计入 50 |
| CPU 时间 / invocation | **10 ms** | **网络等待不计入，但 JSON 解析计入** |
| 同时出站连接 | 6 | 必须做并发闸门 |
| 请求数 / 天 | 100,000 | 按 invocation 计 |

**完整流程的请求量（本地实测推算）**

```
余票 1 + 官方中转 1 + 枢纽枚举 15~20 + 城市多站展开 ×2~4 + 买短乘长 3
最坏 ≈ 85 次        ← 超 50，单次请求装不下
```

**编排方式（D37）**：分段流式。前端分多次请求，每段只查一部分枢纽：

```
请求 1:  直达 + 官方中转 + 前 5 个枢纽      ≈  7 次   ✓
请求 2:  中间 5 个枢纽                       ≈  5 次   ✓
请求 3:  后 5 个枢纽 + 买短乘长               ≈  8 次   ✓
```

每段是独立的 invocation，**各有 50 的配额**，自然分摊。结果到达即追加显示，用户不用等全部完成。

**为何不选扇出转发（D38）**：Master + Node Worker + Service Bindings 虽能把子请求配额提到 1,000（内部服务），但 ① CPU 10ms 问题未解决——master 汇总所有 Node 结果仍要解析全量 JSON；② 复杂度高一个数量级（多 Worker 部署、Bindings 配置、错误传播、超时处理）；③ 分段流式已能解决配额问题，且复用前端本就需要的流式展示。

### 5.3 CORS 实测（决定代理层必须存在）

真实浏览器（Chrome DevTools）页面内 fetch，控制台原文：

```
Access to fetch at 'https://kyfw.12306.cn/otn/leftTicket/queryG' from origin 'http://localhost:8765'
has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present on the requested resource.

Access to fetch at 'https://kyfw.12306.cn/lcquery/queryG' from origin 'http://localhost:8765'
has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present on the requested resource.
```

**易误导现象**：curl 直连余票接口，**带 cookie 时返回 `Access-Control-Allow-Origin: *`**，不带 cookie 则 `302 → error.html` 且无 ACAO。该 cookie（`JSESSIONID`）为 `HttpOnly` 且跨站不发送，浏览器拿不到 → `ACAO: *` 看得见摸不着。且带凭证请求配 `*` 在规范上本就非法。

| 组合 | 结果 |
|---|---|
| 无 cookie 请求余票 | `302 → error.html`，无 ACAO |
| 带 cookie 请求余票（curl） | `200`，`ACAO: *` |
| 浏览器跨站带 cookie | ❌ 做不到（HttpOnly） |

**另一坑**：`/otn/leftTicket/*` 从部分 IP 直连被 WAF 拦成 `302 → error.html`。**必须先访问 `/otn/leftTicket/init` 拿 cookie 再查询**。

### 5.8 票价接口

```
GET /otn/leftTicket/queryTicketPrice?train_no=240000G53108&from_station_no=01
    &to_station_no=13&seat_types=P2&train_date=2026-10-07
→ {"P":"¥1191.0","A2":"¥661.0","2":"6610","WZ":"¥661.0","train_no":"240000G53108"}
```

### 5.10 Cloudflare Workers 可达性（2026-10-04 实测）

用 `tools/workers-probe.js` 在 Workers Playground（免账号）实测：

| 验证项 | 结果 | 含义 |
|---|---|---|
| 出口 IP | `2a06:98c0:3600::103`（Cloudflare IPv6 段） | 未被 12306 风控 |
| 余票 `init` | 200，**cookie 数 3** | `getSetCookie()` 在 Workers 运行时可用 |
| 余票 `queryG` | 200，**55 趟车** | 与本地实测一致 |
| 中转 `lcquery` | 200，有返回 | 免 cookie 路径可用 |
| 枢纽枚举 30 组 | **30/30 全部成功** | 风控非概率性，无部分失败 |
| 单次子请求数 | **34**（2 出发站 × 15 枢纽 + 前置 4） | 占 Free 版 68% |

**结论**：Workers 能访问 12306，代理层架构成立。

**踩到的坑（已在脚本修复）**：模块级 `let SUB = 0` 计数器被 isolate 复用导致跨 invocation 累积，34 次报成 68 次。**Workers 会复用 isolate，模块级可变状态跨请求泄漏**——正式开发时 cookie、缓存等同样不能放模块顶层。

### 5.11 接口错误形态

失败统一返回：

```json
{"status": true, "data": "", "errorMsg": "没有查询到中转方案"}
```

**`status` 永远为 `true`，不能拿它判成功**，必须检查 `data` 是否为空。非法站码与「合法但无方案」返回形态完全一致，无法区分。

## 六、事实纠正

> 以下三处是既有文档中的错误结论，本次实测推翻。**既有文档尚未修改**，以本节为准。

| # | 错误说法 | 出处 | 实测事实 |
|---|---|---|---|
| 1 | `yp_info` 每 10 字符一个席别（座别码 1 + 价格×10 占 5 + 余票 4） | `docs/research/12306中转算法调研报告.md:194` | **`yp_info` 是 Base64 密文**（如 `RvuaEQIXmrGyRnKMUSelt5p9vK1SQlRrYoN2UJV9MP5PF+B7w0Kypa85sm0=`），按该规则解码全为 `NaN`。**价格必须走 `queryTicketPrice` 接口** |
| 2 | `czxx/queryByTrainNo` 已失效（返回空） | `docs/设计方案.md:65` | **可用**，返回完整经停序列（站序/到发/停站时长），正是经停站该用的接口 |
| 3 | 12306 接口无 CORS 响应头 | `docs/部署与架构决策.md` §1.1 | 结论正确但推理不完整：余票接口**带 cookie 时返回 `ACAO: *`**，因 cookie 为 HttpOnly 而浏览器不可用。另 `/otn/leftTicket/*` 在部分 IP 上直连会被 WAF 拦（`302 → error.html`），**必须先取 cookie** |

**站码勘误**（讨论中犯过的错，记录以免重蹈）：十堰 = `SNN`（非 `SYN`）。站码写错会导致「直达 0 趟」的假象。
