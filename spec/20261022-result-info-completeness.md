## 一、问题

用户反馈「现在的样式很难看，按钮和展示的内容很凌乱」。核查后发现，问题不止于样式——**现有实现已经在丢信息**，只是被样式掩盖了：

1. **中转席别只解析了 4 个**。中转响应的 `fullList` 每程有 14 个席别字段，解析时只取 `swz_num` / `zy_num` / `ze_num` / `wz_num`，其余 10 个（`gr_num` 高级软卧、`rw_num` 软卧、`yw_num` 硬卧、`rz_num` 软座、`yz_num` 硬座、`tz_num` 特等座、`gg_num`、`yb_num`、`qt_num`、`srrb_num`）直接丢弃。普速车中转因此只能显示「暂无余票信息」——票就在 `yw_num` / `yz_num` 里，但从没被读过。

2. **中转卡片即使有 4 个席别也只渲染 1 个**。`entries.find(([code]) => code === 'ZE') ?? entries[0]`，优先二等座，没有就取第一个。

3. **自研中转卡片完全不显示余票**。自研取数走 `lite` 解析，`seats` 恒为空数组，组件也从未引用该字段。

4. **公交接驳缺逐段时长**。上游每条线路都有 `duration`，但 `TransitLine` 没映射；步行段的 `duration` 也在累加距离时被丢弃。

5. **跨天标识最多只到 +1**。中转与自研卡片传给 `dayOffset` 的是格式化字符串「6时20分」，匹配不上 `HH:MM` 正则，退化为「到达 < 发车 → +1」。

6. **接驳摘要缺里程与票价**。原始需求（D69）要求接驳方案给出「时间、价格、公里数」，但摘要行只有时间和余量，里程与票价藏在展开详情里。

同时，即使补齐信息，现有版式也撑不住：中转卡片把起终点、总耗时、车次链、换乘站、等待、同站/异站、每程余票、风险标记、接驳入口、参考价全部塞进一张卡片的四列网格，右列尤其拥挤。

## 二、方案

**先补数据，再改版式。**

信息补全（D77~D78）：
- 中转席别从 4 个补到 8 个常见席别，卡片上全部渲染，按程分组
- 自研通路改用完整解析，卡片补上余票
- 公交接驳补逐段时长，步行段也标
- 接驳摘要补齐时间、里程、票价、余量四项
- 修正跨天标识

版式重排（D79）：
- **一条腿一行**：`发时 发站 ── 车次 ── 到时 到站 ── 历时`
- 换乘处独立成行，横跨整宽，左侧竖线标记
- 直达 = 1 段，中转 = 2 段夹 1 个断点，自研 = 3 段夹 2 个断点，三个页面共用同一套结构
- 结果区改为「一整块面 + 行间细线」，不再是每张卡独立圆角加阴影

## 四、实现决策

### 4.1 席别信息（D77）

- **D77 席别覆盖范围**：中转通路解析 **8 个常见席别**——商务座、一等座、二等座、无座、硬座、硬卧、软卧、高级软卧。其余 6 个字段（`tz_num` 特等座、`gg_num`、`yb_num`、`qt_num`、`srrb_num`、以及 `rz_num` 软座）**不解析**：实测样本中它们几乎恒为 `--`，补进来只会让卡片变长而无信息增益。
  - 席别编码统一走一个映射表，键为上游字段名，值为「界面码 + 短名 + 全名 + 排序位」
  - 直达通路的 `SEAT_COLUMNS`（8 个列位）与中转通路的字段名映射**并存**——两者数据来源不同（58 列定长 vs 命名对象），强行合并会引入分支判断
  - 席别在卡片上使用**短名**（二等 / 一等 / 商务 / 硬卧 / 软卧 / 高级软卧 / 硬座 / 无座），在展开详情里使用全名
  - 短名只在卡片摘要层使用，避免与「二等座参考价」这类固定文案冲突

- **D77 席别展示规则**：
  - 每个席别都渲染，不因无票而隐藏——「无」本身是信息
  - `'--'` 与空串表示该车无此席别，不渲染
  - 有票显示 `短名 有` 或 `短名 N 张`；无票显示 `短名 无`
  - 全部席别都不可用时显示「暂无余票信息」
  - 按程分组：第 1 程一行、第 2 程一行；三程行程三行
  - 有票为绿色，无票为灰色

- **D77 自研通路的余票**：自研取数改用完整解析（不再跳过席别对象构造），卡片补上余票行。
  **代价评估**：实测单次余票查询最多 55 趟车（京沪线），自研一次查询约 30 条边 × 55 趟 ≈ 1650 趟；构造 1650 × 8 个席别对象在现代 JS 引擎上是毫秒级，不需要额外的懒加载按钮。

### 4.2 接驳信息（D78）

- **D78 摘要层信息**：接驳摘要行必须同时给出**时间、里程、票价、余量**四项，不要求展开。票价仅在上游给出时显示；打车价同理（承接 D76：不本地估价）。
  - 布局为「方式 | 耗时 | 里程 | 票价 | 余量」，余量靠右对齐便于竖读
  - 余量 = 换乘等待 − 接驳耗时；为负时显示「超 N 分」并标红

- **D78 公交逐段时长**：解析层保留每一段（含步行段）的时长与距离，摘要之下逐段列出。
  - 步行段只显示距离与时长——上游 `WALKING` 步骤没有起止站名，**不编造路径描述**
  - 乘车段显示线路名、上下车站、经停站数、时长
  - 段末给出步行合计与换乘次数（上游无汇总字段，由解析层累加）
  - 时长靠右对齐，竖读可比

- **D78 过路费**：`> 0` 时才出现，与打车费同行或独立一行，不得显示「过路费 ¥0」。

### 4.3 跨天标识（D79 之一）

- **D79 跨天修正**：时刻展示组件改为接受**分钟数**（而非格式化字符串），内部自行格式化。
  - 跨天天数由「发车时刻 + 历时分钟数」计算，跨 2 天以上正确显示 `+2`、`+3`
  - 三个调用点（直达、官方中转、自研中转）统一改传分钟数
  - 直达通路的 `Train.duration` 是 `HH:MM`，调用点负责转成分钟

### 4.4 版式重排（D79）

- **D79 核心结构：一条腿一行**。三个结果页共用同一个「行程段」结构：
  ```
  发车时刻  发车站  ── 车次 ──  到达时刻  到达站      历时
  ```
  - 直达 = 1 段
  - 官方中转 = 2 段，中间一个换乘断点
  - 自研中转 = N 段，中间 N−1 个换乘断点
  - 车次压在轨道线上（用背景色遮断），历时在轨道线下方

- **D79 换乘断点**：独立成行，横跨整宽，包含：
  - 换乘等待时长（按充裕 / 紧张 / 来不及着色）
  - 「到达站 → 下一程出发站」
  - 「同站 / 同城异站」短标签（同站时可省略）
  - 风险标记
  - 接驳入口（文字链，非块状按钮）
  - 左侧竖线标记，**不使用贯穿虚线**（会被文字割断）

- **D79 结果区容器**：整块白面 + 行间细线，取代「每张卡独立圆角 + 阴影」。分组标题、方案行都在同一块面内。

- **D79 层级与字号**：
  - 时刻 19px/600（桌面）、17px/600（窄屏）、16px/600（≤380px）
  - 数字统一 `tabular-nums`，保证列对齐
  - 元信息 12.5px，微标 11px
  - 不使用 webfont——CJK webfont 动辄数 MB，车站手机流量场景不可接受；辨识度来自字号层级与数字对齐

- **D79 色彩语义**：颜色只用作信号，不做装饰。
  - 有票 / 余量充裕 → 绿
  - 接驳紧张 / 超长等待 → 琥珀
  - 无票 / 时间不足 → 红
  - 其余全部灰阶
  - 深浅色两套变量，跟随系统

- **D79 响应式**：
  - 桌面：时刻与站名同行，车次压在轨道线上
  - ≤700px：车次与历时折到时刻行下方，轨道线横跨整行
  - ≤380px：公交逐段改为「方式 + 时长」一行、「站名」一行
  - 320px 无横向溢出

- **D79 接驳入口**：由 44px 块状按钮改为文字链。这与 D54「主要操作点击区域不小于 44px」的张力——**接驳入口不是主要操作**，主操作是查询按钮与查价；文字链通过增加行高与内边距保证可点区域，视觉重量让给内容。

### 4.5 技术决策（T63~T66）

- **T63 席别映射表**：新增一张「上游字段名 → 席别描述」的映射，放在共享常量层，由解析层消费。描述包含界面码、短名、全名、排序位。解析层不硬编码字段名。
- **T64 公交逐段模型**：`TransitPlan` 增加「段列表」，每段含类型（步行 / 乘车）、时长、距离、线路信息（仅乘车段）。原有的 `lines`、`walkMeters`、`transfers` 保留——它们是汇总值，段列表是明细，两者不互相替代。
- **T65 时刻组件入参**：`JourneyTimes` 的 `duration` 入参由字符串改为分钟数；格式化与跨天计算在组件内部完成。调用点负责把 `HH:MM` 转成分钟。
- **T66 自研解析**：`selfbuilt-adapter` 改用完整解析。原有的「跳过席别对象构造」选项保留（仍用于其他不读席别的场景），但自研通路不再传该选项。

## 五、测试决策

**好的测试**：只断言外部可见行为——给定上游响应得到什么展示模型；不针对内部调用顺序、私有函数或 DOM 结构细节。网络一律注入。

**信息完整性是本轮的首要保护目标**：每条「补回来的字段」都要有测试，且测试断言的是**字段存在与取值**，不是「渲染了几个 DOM 节点」。

| **S6** | `ConnectionPanel` 组件（jsdom） | 摘要含时间 + 里程 + 票价 + 余量；逐段时长按序渲染；9 个降级分支文案 | `ConnectionPanel.test.tsx` 已有 200 行覆盖 |

**主接缝是 S1 与 S2**——数据丢失的根因都在解析层，这里测住了，下游渲染就不可能缺字段。

**不测**：颜色、间距、断点像素、深浅色具体取值。这些靠截图与人工验收；写进测试只会让测试随样式调整而碎裂。

**回归基线**：现有 395 条测试全部保留，改版不得删除任何一条断言；如断言因版式变化而失效，改为断言同一信息的等价表达，不得直接删掉。

## 七、其他说明

### 已确认的实测结论

- **中转响应的席别字段**：`fullList` 每程含 14 个 `*_num` 字段。真实样本（北京→西安，2026-10-25）中普速车 T55 返回 `rw_num=1`、`yw_num=14`、`yz_num=有`，三项当前全部被丢弃。
- **单次查询规模**：京沪线单次余票查询 55 趟车；中转响应 `fullList` 总条数约 20 条。lite 解析省下的开销在此量级可忽略。
- **打车费**：承接 D76，`taxi_fare` 在 ≤50 km 区间基本不返回，故打车价多数时候不显示。

### 与既有决策的关系

- **D54 / D55**：视觉基调（Apple 风格、系统字体、跟随系统深浅色、展示内容不变）继续有效。本规格的版式重排是**在 D55「展示内容不变」框架内**的重排，且额外补回了 D55 制定时尚未丢失的字段。
- **D69~D76**：接驳的产品口径全部有效。本规格只补 D69 未落实的「价格、公里数」在摘要层的呈现，以及 D78 的逐段时长。
- **D31 合规底线**：不变。补席别与逐段时长都不增加请求数——数据本来就在响应里。

### 验收方式

1. 现有 395 条测试全绿
2. 新增测试覆盖 S1~S6
3. 原型 `docs/ui-prototype-v2.html` 与实现逐屏比对：直达 / 官方中转 / 自研中转 / 枢纽选择 / 接驳 9 种降级分支
4. 320px / 390px / 768px / 桌面四档宽度无横向溢出
5. 浅色 + 深色两种主题下信息均完整可读
6. 逐条对照四份盘点清单，确认无字段丢失
