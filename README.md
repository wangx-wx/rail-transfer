# rail-transfer

12306 中转换乘查询工具 —— **比官方网页给出更多中转方案**。

> 状态：**v1 骨架已建成并端到端跑通**（零依赖、零构建）。

## 一句话背景

12306 官方帮助页自己写明：中转换乘功能只查询「途中换乘**一次**的**部分**列车余票情况」。
根因是候选枢纽在服务端被截断成 Top-N（官方专利 `CN114912659A` 实施例 n=10）。

本工具通过**强制枚举候选枢纽**把这批被截断的方案补回来。实测兰州→杭州：
官方默认给 9 条，额外枚举 8 个枢纽后多拿到 29 条，其中武汉 / 西安 / 上海 / 长沙 / 徐州
**完全不在官方默认候选清单里**。

---

## 算法选型

采用**路线 B：官方 Top-N 复用 + 强制枢纽枚举**。

```
Step 0  预售期校验（D 必须在 [今天, 今天+14]）
        ⚠️ 越界时返回 302→error.html，页面显示"查询超时"，与网络故障无法区分
Step 1  调 1 次空 middle_station 的 queryG → 官方默认方案 + 候选站种子
Step 2  对候选枢纽清单逐个调 queryG，用 result_index / can_query 分页取完
Step 3  合并去重
Step 4  硬约束过滤：最小换乘时间 + 无回头路线
Step 5  自研打分排序（官方 score 是黑盒，不直接采用）
```

不采用全站暴力穷举（3404 站）、离线时刻表自建图（193MB 数据）、
全路 OD 预计算（需离线集群，且**它正是"方案不全"的根因**）。

## 部署架构

**纯 GitHub Pages 走不通** —— 12306 接口无 CORS 响应头、OPTIONS 预检 302、
不支持 JSONP（实测见 [`docs/部署与架构决策.md`](docs/部署与架构决策.md)）。必须有代理层。

```
浏览器  →  代理层（本地 Node → 未来可换 Cloudflare Workers）  →  12306 内部接口
```

分两阶段：**当前阶段**服务端跑 localhost（零合规风险）；
需要外网访问时再启用 Cloudflare Workers（免费额度 10 万请求/天，但需注意
同时出站连接仅 6 个、子请求 50 个/次）。

## 快速开始

**零依赖、零构建**，无需 `npm install`（Node 24+）：

```bash
node --test                 # 跑全部测试
node tools/dev-server.mjs   # 本地开发服务器（默认 http://localhost:8765）
node tools/gen-stations.mjs # 重新生成城市站表（纯静态，零网络）
```

开工前的接口复核脚本（历史资料）：

```bash
node spike/recheck/t.mjs    # 验证城市代表站展开行为
node spike/recheck/t2.mjs   # 验证无关/反向枢纽与目的地站过滤
```
